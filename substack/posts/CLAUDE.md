## Voice & Tone Guidelines

### What Works for Substack Thought Leadership
- **Educational first** - Teach the framework, don't sell the service
- **Direct and specific** - Use concrete numbers, real company examples
- **Generous with expertise** - Give away the methodology (readers can apply it themselves)
- **Understanding organizational reality** - Acknowledge why teams struggle (PMM underwater, priorities shift)
- **Let work speak** - Examples and rewrites demonstrate competence without self-promotion

### Avoid
- Heavy CTAs or conversion optimization language
- Qualifier sections ("this is for you if...")
- "What you'll get" boxes
- Urgency tactics ("limited slots available")
- Over-explaining why readers need external help (they can figure that out)

### Keep
- Light, one-line CTA at the end
- Framework-focused (teach the 3 questions)
- Real examples with specific critiques
- "Neera rewrites" showing alternative copy

## Repeatable Editing Workflow

**Use this workflow for all Substack posts.** These are the process patterns that emerged from editing Issue 3, applicable to any future post.

### Pre-Edit Phase

**1. Clarify Goals First**
- [ ] What is this post trying to accomplish? (thought leadership? education? conversion?)
- [ ] Who is it for? (And who is it NOT for?)
- [ ] What should the reader be able to DO after reading it?
- [ ] Check these against project goals in CLAUDE.md
- [ ] If goals aren't clear, ask before editing

**2. ICP Roleplay**
- [ ] Read the entire draft as the target ICP, not as the author
- [ ] Note where you get confused, bored, or lost
- [ ] Identify "wait, but what about...?" questions
- [ ] Document what's missing FROM THE READER'S PERSPECTIVE
- [ ] Use this to guide structural edits

### Editing Passes (In Order)

**3. Structural Edit**
```
Order: Cut → Move → Add sections
Don't edit sentences until you know if the section should exist
```
- [ ] Cut entire sections that don't serve the goal (save them to "cut material" file)
- [ ] Move sections to logical order
- [ ] Add missing sections
- [ ] For each section, write its "job" in one sentence (if you can't, cut it)

**4. Transition Pass**
```
Read ONLY:
- Last sentence of Section A
- First sentence of Section B
Does B follow naturally from A?
```
- [ ] Review each section boundary
- [ ] Add bridging sentences where jumps are jarring
- [ ] Cut redundant setup ("As I mentioned earlier...")

**5. Consistency Audit**
- [ ] Search for repeated phrases (intentional vs. accidental?)
- [ ] Check if key terms are defined on FIRST use
- [ ] Remove repeated disclaimers (say it once, not every time)
- [ ] Verify structural elements are consistent (tables, headers, format)

**6. Lens-Specific Passes**

Run separate passes for different evaluation criteria:

**Written Communication Lens:**
- [ ] Does it lead with conclusion, not build up to it?
- [ ] Cut preamble (start at the "bear attack")
- [ ] Turn bullet fragments into full sentences where logic matters
- [ ] Read aloud for rhythm

**Positioning/Messaging Lens:**
- [ ] Run swap test on major claims (can a competitor use this language?)
- [ ] Check for transformation moments (before/after with specifics)
- [ ] Verify customer language vs. marketing language
- [ ] Confirm one primary buyer is named

**7. Verify Claims**
- [ ] Flag every metric, timeline, or specific outcome
- [ ] Ask: Where did this number come from?
- [ ] Cross-check against sources (websites, case studies, testimonials)
- [ ] If unverified, either soften ("likely," "suggests") or replace with verified language

**8. Apply Framework to Itself**
- [ ] If teaching a framework, apply it to your own examples
- [ ] Check for hypocrisy (do you violate your own rules?)
- [ ] Ensure examples follow the framework you're teaching

**9. Readability Pass**
- [ ] Sentence-level clarity (no run-on sentences >40 words)
- [ ] Simplify awkward phrasing
- [ ] Cut redundant words ("in order to" → "to")
- [ ] Remove filler ("the reality is," "the fact that")

**10. Final ICP Read-Through**
- [ ] Read once more as the target reader
- [ ] Confirm gaps from step 2 have been addressed
- [ ] Check: Can they DO what the post promised?

### Post-Edit Phase

**11. Save Cut Material**
- [ ] Move cut sections to `Issue X/cut-material.md`
- [ ] Note where each piece might fit (different post, different medium)
- [ ] Review this file when planning future posts

**12. Update CLAUDE.md**
- [ ] Document what was implemented
- [ ] Update change log
- [ ] Note any decisions made (and why)

### Quick Reference: Common Editing Mistakes

**DON'T:**
- Edit sentences before confirming sections should exist
- Polish writing you might delete later
- Edit for everything at once (structure AND line edits simultaneously)
- Cut good writing without saving it for later
- Make claims you can't verify

**DO:**
- Structure first, sentences last
- Separate passes for different lenses
- Read as your ICP, not as yourself
- Save cut material for future posts
- Verify claims before publishing

### Editing Order Cheat Sheet

```
1. Clarify goals
2. ICP roleplay (find gaps)
3. Structural pass (cut/move/add sections)
4. Transition pass (connect sections)
5. Consistency audit (repeated phrases, undefined terms)
6. Lens passes (written comm, positioning, accuracy)
7. Verify claims
8. Apply framework to itself
9. Readability pass
10. Final ICP read
11. Save cut material
12. Update CLAUDE.md
```

**Golden Rule**: Structure → Flow → Content → Readability

Edit in this order, not all at once.
